## 規則と読み方

候補辺の本数は0・1・2。辺は同じ行・列で隣り合う星同士。座標は元データの0始まり、星番号・辺番号は配列順の1始まりで、画面に出ている番号ではない。

1. **数字**：その星の必要本数と、他の辺の最小・最大合計に合わない候補を除く。
2. **＋交差**：最低1本と確定した辺に交差する辺を0本にする。数字と繰り返す。
3. **＋連結**：残候補グラフからある1辺を除くと全体が分断する場合、その辺を最低1本にする。数字・交差と繰り返す。

3は連結規則全体を扱う完全な推論器ではない。「2本の接続候補のどちらかは必要」といった組合せは直接保持しない。数字だけの対照条件は、同じ評価関数に交差の関連を空にして渡している。保存正解は全段階の推論終了後に誤排除を確認するためだけに使う。

以下の「確定」は0本の辺も含む。「交差で候補減」は＋交差段階の履歴件数で、人の操作数・必要な手順数ではない。順番次第で数字でも消える候補が交差で先に消える場合がある。「連結で候補減」も同様で、発火しただけで連結が不可欠とは言えない。全22面で＋連結の最終確定数は＋交差と同じだった。

## 優先確認する代表3面

### 1. 第15夜：数字から交差排除への切替

直前の第14夜は15/15辺が数字だけで確定する。第15夜は星が13→17に増え、数字だけでは11/19辺まで。交差を使うと19/19辺が確定する。

具体的には星10=(5,1)の数字4は、隣接する2辺をそれぞれ2本にする。星10―9=(5,4)の縦線に交差する星6=(3,2)―4=(6,2)を0本、星11=(0,1)―10の横線に交差する星8=(1,0)―3=(1,2)を0本にできる。この2つは数字だけで止めた時点では各0/1候補が残っている。後者が0本なら数字1の星8は星5=(6,0)へ1本と決まり、数字の連鎖が再開する。

確認候補：**「線を増やす」だけでなく「交差する線を置けないと判断する」見方を、この面の説明候補として具体化する**。既存ルール以外の知識は使っていないが、プレイヤーが交差禁止を自力で推論に使えるかは未測定。

### 2. 第18夜：1本ずつの連結確認では拾えない集まり

直前の第17夜は数字だけで21/21辺が確定する。第18夜は3段階とも12/20辺で止まり、8辺に各2候補が残る。残候補256通りだけを検算すると、数字一致2配置、交差禁止も満たす2配置、連結するのは1配置だった。

不正なもう1配置では、星の集まりが `{1,2,3,4,5,7,8,9,10,12,13}` と `{6,11,14,15,16,17}` に分かれる。両集まりを結ぶ候補は辺4（星2―6）と辺16（星14―7）。この配置では両方0本で、正解では両方1本。各辺を単独で候補グラフから除いてももう一方が残るため、今回の単純な連結規則は候補を減らせなかった。残候補はJSONの `representative_checks` に全配置を記録した。

確認候補：**「この集まりを外につなぐ道が残るか」を、第18夜で説明する必要があるかを優先して実プレイ確認する**。数字・交差だけを満たす別配置が実在するので、この面の正解判定には連結条件が区別に効く。ただし人間が仮置きや256通りの列挙をしなければ解けない、という意味ではない。

### 3. 第24夜：交差を除いた後も連結の見落としが残る

直前の第23夜は＋交差で27/27辺が確定する。第24夜は候補辺が25に減っても、数字10/25、＋交差・＋連結13/25で止まる。12辺の残候補4,096通りを上限付きで検算すると、数字一致3配置→交差禁止2配置→連結1配置となった。
