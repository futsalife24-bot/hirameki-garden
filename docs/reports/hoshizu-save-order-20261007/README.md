## 9ケースの比較結果

全ケースは新規に作った架空データです。途中状態は収録解の最初の2組だけを通常操作で置ける形、完成状態は収録解をそのまま使っています。全30夜クリアのベストも架空の値で、新しい解探索はしていません。

「旧順が既知」の列は、**入力が変更前の順序から来たと保証できる場合だけ**、メモリ内で対応する面番号とベストのキーを読み替えて現行の復元関数へ渡した比較です。実保存へ書き戻す変換器は作っていません。

| 架空状態 | 無変換で順序だけ変えた結果 | 旧順が既知なら保てる部分と残る問題 |
| --- | --- | --- |
| 保存なし | 第一夜から。差なし | 第一夜から。差なし |
| 第一夜クリア→第二夜未着手 | 同じlevel=2が旧第三夜を指す | 旧第二夜を続けるなら新第四夜に対応 |
| 第二夜途中 | `0-4`の線が消え、残る`0-2`も別座標の線になる。手数3は残る | 新第四夜にすれば元の線・手数を保持できる |
| 第二夜クリア直後 | 6組の線のうち4組が消え、残る2組も別座標。完成true→false、手数8は残る | 新第四夜で完成を保持。ただし次へ進むと旧第五夜になり、未プレイだった旧第三・第四夜を飛ばす |
| 第三夜途中 | 2組のキーは残るが両方とも別座標。別問題の途中になる | 新第二夜で元の途中盤を保持。ベストは新第一・第四夜に対応する |
| 第一〜四夜クリア直後 | 旧第四夜から旧第二夜へ変わり、線2組が消え、完成true→false | 新第三夜で旧第四夜の完成を保持。ただし次は既クリアの旧第二夜を再度出す |
| 第一〜四夜クリア→第五夜未着手 | 第五夜の盤は同じ。ただしベスト2・3・4の対応は間違う | 盤は第五夜のまま、ベストの値を対応付ける必要がある |
| 全30夜クリア直後 | 第三十夜は完成を保持し、次は第一夜。ただしベスト2・3・4は別問題に対応 | 第三十夜→第一夜を保持。ベスト2・3・4は対応付けが必要 |
| 全30夜クリア後の第一夜途中 | 第一夜の線は同じ。過去ベスト2・3・4は別問題に対応 | 第一夜の線を保持し、過去ベストだけ対応付けが必要 |

この9ケースでは、旧順と既知の読み替え後に、**現在の元問題・線・手数・完成状態・過去ベストが指す元問題の集合**が保持されることを確認しました。クリア後の進み方まで同じとは言えない点が、保存の対応だけでは済まない理由です。

ベストはキー集合が同じでも安全とは限りません。架空の第一〜四夜ベストは変更前が `{"1":10,"2":8,"3":7,"4":8}`。問題を保って候補順へ対応させると `{"1":10,"2":7,"3":8,"4":8}` になります。数値は実プレイの測定値ではありません。

## 保存だけから元の問題を特定できない反例

次の組合せは、旧順・候補順のどちらでも「第一夜をクリアして次へ進む」と自然に作られます。第一夜は両方で同じ問題です。

```json
{
  "hoshizu-save-v1": {"level":2,"b":{},"moves":0,"solved":false},
  "hoshizu-best": {"1":10}
}
```

- 旧順なら、今から遊ぶのは**旧第二夜**。
- 候補順なら、今から遊ぶのは**旧第三夜**。

JSONは全く同じです。線が空のため形から照合することもできません。保存時の問題ID・順序版がないので、**出自が混在した後の保存単体からは正しい変換先を一意に復元できません**。盤の形や手数から推測して変換する案は採りません。

これは「現在の全既存保存が変換不能」という意味ではありません。今回確認した公式履歴では問題順が変わっていないため、変更前のデータと確定できれば旧順の対応は計算できます。ただし同じv1キーへ候補順の保存を書き始めた後、どちらの版で書かれたかを示す情報なしで後付け判定することはできません。

また、無変換版で一度起動して線を捨てた後は、残ったJSONだけでは捨てられた線を取り戻せません。元JSONを保持する方法・移行済みの識別・複数キーの整合性・旧版オフライン復帰時の扱いは、将来もし順序案を採用するなら検討が必要ですが、今回は新schemaや製品移行処理を実装しません。

## 現順維持の案と比較した判断

| 観点 | 順序を1→3→4→2へ変える案 | 現順を保ち孤立の任意案内を加える案 |
| --- | --- | --- |
| 現在の途中盤 | 旧問題との対応と版の出自を扱う必要あり | 順序・保存形式を変えなければ現行復元のまま |
| ベスト | 面番号の2・3・4を対応付ける必要あり | 元の面番号のまま使える。ただし案内で容易になれば以前のベストと条件差は生じ得る |
| 次へ・既クリア | 未プレイ面を飛ばす/既クリア面を再度出すケースがあり、進行方針の判断が必要 | 現在の順次進行・30→1を維持できる |
| 保存の出自 | 同じv1のまま新旧が混じると識別不能 | 順序を変えなければ今回の識別不能問題を追加しない |
| 新しく必要な確認 | 保存・復元・ベスト・進行・更新前後の整合性 | 案内の仕様・表示条件・見切れ・実際に役立つか |

今回の証拠からは、**次に具体化するなら現順維持の任意案内を優先する**のが低負担と判断します。順序変更案を採用するなら、現在の問題を保つだけでなく「残りをどの順に遊ばせるか」という本人の仕様判断が必要です。どちらの製品変更も今回の依頼には含まれないため、未採用の比較資料としてここで止めます。
